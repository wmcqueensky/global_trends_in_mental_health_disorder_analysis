Passing Criteria & Evaluation Policy

    Overall Passing Threshold: You need an overall cumulative score of at least 50% across all weighted components to pass the course.

    Cumulative Grading (No Minimum Per Component): You do not need to pass each component individually (e.g., there is no requirement to score 50% on short tests specifically).

    Flexibility: It is entirely possible to achieve a positive final grade even if you perform poorly on or skip short tests, as long as your total score across all components equals or exceeds 50%.

    Exception: The only mandatory non-numerical requirement is submitting the Individual Project on Moodle (No Moodle submission = automatic fail).
    Attendance: Class attendance is not mandatory. Short tests, however, take place in class, so you can only earn those points by being there.

b. Format: Google forms test consisting of 5 multiple-choice questions (A–D).

1 correct answer per question

2 points per correct answer (10 points total)

Content: Mix of code questions and lecture slides covering the previous two weeks.

Attendance Policy: You are allowed to miss 1 short test without penalty (best 3 out of 4 count).

When and where: Tests are taken on google forms sent via email by dr Ewa Weychert, during the last 15 minutes of the session. For example, if your USOS group meets on Friday 8:00–9:30, the test runs 9:15–9:30. Make sure you are able to take the test online at the end of class in test weeks (4, 6, 8, 10).

⏱ Deadline January 06, 2027 by 23:59 via Moodle

Critical Rules

    No Moodle Submission = Automatic Failure: Failing to submit on Moodle results in an automatic failure for the course.
    Moodle Only: Submissions outside of Moodle (e.g., via email or late upload) will not be accepted.

File Formatting Requirements

    Format: Single .zip archive only.
    Content: Include ONLY source code files (e.g., .py or .ipynb).
    NO DATASETS: Do not include raw data or database files in the archive. Datasets are usually too large and exceed Moodle size limits.

Submission Workflow

[ Code Files ] → [ Zip Archive ] → [ Upload to Moodle ]

Required .ZIP File Structure (Code Only)

README.md — Must contain:

a. Direct link to the external dataset (e.g., Kaggle, Open Data portal).

b. Recommended execution order for reading and running scripts.

c. Brief description of what each file does.

d. Instructions to run the Streamlit app.

    App.py (or main.py) — Streamlit presentation layer.
    Scripts/ or source files — Data wrangling, custom logic functions, and SQL setup scripts.
    requirements.txt — List of required Python packages (e.g., pandas, streamlit, seaborn).

Recommended .zip Naming Conventions

    Standard Format: [Surname]_[Firstname]_[StudentNumber]_Project.zip (Example: Smith_John_123456_Project.zip)

    Avoid Spaces & Special Characters: Use underscores (_) or hyphens (-) instead of spaces, and stick to standard Latin characters.
